# TOTVS Insight

React 19 + Vite + Tailwind CSS v4. Dashboard for analyzing commercial meeting
transcripts.

This project **was** generated by Figma Make and has since been decoupled from
it: no `.figma/` directory, no Figma plugins in `vite.config.ts`, and fonts are
served from `src/assets/fonts/` instead of `static.figma.com`. It is a plain
Vite app — `pnpm dev`, `pnpm build`, deploy anywhere. Do not reintroduce a
dependency on Figma tooling.

## Development server

```bash
pnpm install
pnpm data:build   # required once — see "Data layer"
pnpm dev          # http://localhost:8443
```

## Deploying

See `DEPLOY.md`. **Read it before publishing anywhere**: the login is
client-side only, so the meeting transcripts under `public/data/` are readable
by anyone with the URL. Use `pnpm data:build:publico` to build without them.

## Data layer

Meeting data comes from `data-source/ANON_transcricao.json` — **NDJSON** (one JSON
object per line, not an array) with sparse records: fields are omitted when null.

`pnpm data:build` runs `scripts/build-data.mjs`, which splits that 46 MB dump into
two artifacts under `public/data/`:

- `meetings-index.json` (~470 KB) — metadata for all meetings, fetched once at boot
- `transcricoes/<id>.json` — one transcript per file, fetched only when opened

`pnpm data:build:publico` generates the index **only**, and marks it
`transcricoesDisponiveis: false` so the transcript panel explains the absence
instead of erroring. Use it for any deploy without server-side auth — the files
under `public/data/` are static and readable by anyone who guesses the URL.

`data-source/` and `public/data/` are both gitignored: the dump is client
conversation content and the artifacts are generated. Run `pnpm data:build`
after cloning, or the app renders its "base não encontrada" error state.

**All data access goes through `src/data/repository.ts`.** Components never fetch
or parse. To swap the static files for an API, rewrite `carregarIndice()` and
`getTranscricao()` there — the exported functions and types stay the same. Pair
loaders with `useDataset()` for `{ data, loading, error }`.

Fields with no source in the data (sentiment, churn risk, opportunities, report
history) stay in `src/data/mockData.ts` and are documented as such. Do not
present derived guesses as if they came from the base.

## Dependencies

- Runtime: React 19 and React DOM 19
- Styling: Tailwind CSS v4 with the `@tailwindcss/vite` plugin
- Build tooling: Vite 8, TypeScript 5.7, and `@vitejs/plugin-react`
- Formatting: oxfmt

## Styling

This project uses **Tailwind CSS v4** through the `@tailwindcss/vite` plugin configured in `vite.config.ts`. `src/index.css` imports Tailwind with `@import 'tailwindcss';`. Use Tailwind utility classes directly in JSX and put global CSS or Tailwind v4 theme customization in `src/index.css`. This scaffold does not need a Tailwind config file or PostCSS config.

`src/main.tsx` imports `src/index.css`, so global font wiring belongs in `src/index.css`. Keep CSS `@import` statements first, then add any `@font-face` rules and font-family defaults there.

## Code quality

- Use double quotes for strings containing apostrophes (`"We're here to help"`), or escape them in single-quoted strings. An unescaped apostrophe in a single-quoted string breaks the build.
- Ensure JSX tags are closed and braces are balanced.
- Export components as default exports.

### `pnpm build` does not typecheck

esbuild strips TypeScript types without checking them, so the build passes on
code `tsc` would reject. **Always gate on `npx tsc --noEmit`**, not on the build
alone.

This bit us once: oxfmt 0.2.0 (the version originally pinned) corrupted type
syntax — stripping `;` separators inside inline object type literals, and
dropping the parentheses in `(keyof Reuniao)[]` so it became `keyof Reuniao[]`,
a different type that still parsed. `pnpm build` reported success throughout.
The formatter is now pinned to 0.62.0, where both bugs are gone.
